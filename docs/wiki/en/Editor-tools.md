# Editor tools (MCP)

[Home](Home.md) · [Español](../es/Herramientas-del-editor.md)

The agent sees these tools as `godot.<name>` (Claude Code shows them as `mcp__godot__<name>`).

**Compact tool list** (on by default, **Settings → MCP server**): every tool description takes context on every turn, so the tool list only carries the core (reading, diagnostics, scene editing and running the game) plus two more:

- `godot.methods` lists the other tools, one line each (`query` filters; `method` shows its description and parameters);
- `godot.run` calls one: `{"method": "tilemap_set_cells", "params": {…}}`. It validates the parameters and asks the same permission as the tool itself.

The extra ones are API docs (`class_info`, `search_api`), project settings, the Asset Store, files, resources, tilemaps, animation and the live game. With the compact list, tools/list goes from about 30,000 characters to about 11,000. The setting applies from the next session.

| Group | Tool | What it does |
|---|---|---|
| Read | `project_info` | Godot version, editor binary, project name, main scene, autoloads, input actions, plugins, renderer. |
| | `list_files` | Project files with their resource type; glob filter. |
| | `scene_tree` | A scene's tree: types, scripts, instanced scenes, groups and non-default properties. Without `scene`, the open scene with its unsaved changes. |
| | `project_map` | The files most related to `focus` (paths, class_names, autoload or file names; default: the scene and script open in the editor), ranked, with each script's signals, public functions, exports and enums by line, each scene's nodes and saved connections, and where each script is used. Fits in `max_tokens` (2000 by default). |
| | `get_node` | One node in detail: non-default properties, script, groups, saved signal connections and children. |
| | `editor_state` | Current and open scenes, selection, open script with the caret line, and whether the game is running. |
| | `class_info` | The API of a class in the open editor's Godot version: inheritance, method signatures, properties with defaults, signals, constants, with descriptions. Engine classes, built-in types (`Vector2`…), `@GlobalScope` and project `class_name`s. `member` gives one member's full docs. |
| | `project_settings` | Settings under a prefix with value and default; without a prefix, the ones that differ from the default. |
| | `search_api` | Finds classes and members by name or capability ("raycast", "move toward"). |
| Diagnostics | `get_errors` | Errors and warnings from the editor and the last run. It returns a mark; pass it as `since` to see only new ones. |
| | `validate_scripts` | Parses scripts in a separate process (the editor's binary) and returns errors by file and line, without running the game. In a C# project it also compiles with `dotnet build`. |
| | `validate_physics`, `validate_tilemap` | Read-only checks the agent runs after touching physics or maps: bodies and areas without a shape, shapes outside a body, collision masks that match no layer in the scene; TileMapLayers without a TileSet, cells the TileSet doesn't have, placed tiles without collision. |
| | `capture_editor_viewport` | An image of the 2D/3D viewport. |
| Edit scenes | `add_nodes` | A whole subtree in one call and one undo step: nested nodes with type, properties, script, groups and instanced scenes. Nothing is created if one item is invalid. |
| | `duplicate_node` | Copies a node with its children, script, groups and properties; next to the original or under another parent. |
| | `add_node`, `set_properties`, `remove_node`, `reparent_node`, `rename_node`, `connect_signal`, `instantiate_scene`, `open_scene`, `save_scene` | Edits on open scenes, each one an undo step in the editor. |
| Edit files | `create_scene`, `attach_script` | New scenes and scripts on disk (`.gd`, or `.cs` in Godot .NET, created as a partial class named like the file). `create_scene` also takes the root's script and properties (exported variables included), so a scene is never written by hand. |
| Project | `set_project_setting`, `set_input_action`, `remove_input_action`, `set_autoload`, `remove_autoload` | Project settings, input actions (keys, mouse, joypad) and autoloads through the editor: each change is an undo step and saves `project.godot`. Editing `project.godot` by hand is rejected. |
| Asset Store | `asset_search`, `asset_details`, `addons_list` (read), `asset_install`, `plugin_enable` | Search the [Godot Asset Store](https://store.godotengine.org) for this Godot version, read an asset's page, license and releases, and list the project's plugins. `asset_install` downloads a release and writes only what goes in `addons/` (unless `include_other_files`), never overwrites a file and enables its plugins; it's in its own permission group, **Install from the Asset Store**, which asks in every mode. `plugin_enable` turns a plugin on or off (not the harness). `addons_list` with `check_updates` finds newer releases of the project's plugins, and `asset_install` with `update` replaces the installed version. Paid assets are bought on the store website. |
| Tilemaps | `tileset_add_atlas`, `tileset_add_scenes`, `tilemap_set_cells`, `tilemap_paint_terrain`, `tilemap_clear` (+ `tilemap_get` to read) | On a `TileMapLayer`: a texture becomes an atlas (tiles for every non-transparent cell, optional full collision), tiles by cell or rectangle, terrains already set up in the TileSet, and an ASCII map with a legend to read it. Each change is an undo step. |
| Animation | `animation_create`, `animation_set_track`, `animation_remove`, `sprite_frames_set` (+ `animation_get` to read) | Animations of an AnimationPlayer with value tracks (keys converted to the property type) and method tracks; SpriteFrames of an AnimatedSprite2D/3D from images or a sprite sheet. Each change is an undo step. |
| Resources | `create_resource`, `set_resource_properties` (+ `get_resource` to read) | `.tres` files of a Godot class or a project `class_name`, with sub-resources inline (`{"type": "StyleBoxFlat", …}`) and typed arrays. Changes are an undo step and are saved. Writing a `.tres` by hand is rejected. |
| Files | `move_file`, `copy_file`, `delete_file` | Move or rename keeping the uid and rewriting every `res://` reference and the relative `preload`/`load`/`extends` paths of scripts; copy as a new resource (also from outside the project); delete only if nothing references it (to the trash). `mv`, `cp` and `rm` on project files are rejected. |
| Run | `run_scene` | Runs a scene (with simulated `inputs` if you want) and returns the real errors. With `continue_on_error`, a script error doesn't stop the game in the debugger: it goes on and every error is listed (a breakpoint still stops it, and after 30 errors in one run it stops skipping them). Playtests and the One-shot evaluator use it; Build doesn't, because there it's better to stop at the first error. With `film_fps` (2 to 10 is plenty) it keeps small frames of the run to look back with `game_frames`, without fixing the game's frame rate the way `record` does. With `monitors: true` it measures performance during the whole run and adds the same summary as `game_monitors` at the end. The game ignores the gamepads connected to your computer, so a tilted or drifting stick doesn't move the player or the UI focus while the agent plays; the gamepad events the agent sends still work, and `real_gamepads: true` lets you play along with yours. |
| | `capture_game_frame` | A frame of the running game. |
| | `profile_run` | Runs a scene like `run_scene` with Godot's script profiler on and lists the hottest GDScript functions by self time: `path:line`, calls, self and total ms per frame, share of script time, and whether the function is typed. The profiler slows every call (about 80–100 ns each), so compare functions with each other and measure before and after a change with the same tool. It reads the profiler through an internal editor API (Godot doesn't pass that data to plugins): in a Godot version that changes it, it answers with an error saying so. It doesn't start while a `run_scene` is in progress and always turns the profiler off at the end. |
| | `stop_scene` | Stops it. |
| | `run_regressions` | Runs the saved playtest regressions without an agent turn, `repeat` times each (only those whose goal contains `goal`, if given), and says how many runs of each passed. A regression passes only if every run does; one that passes some runs is flaky, and the count is saved with it. The same as **Run regressions** in the findings panel (see [Review](Review.md)). |
| | `write_regressions_workflow` | Writes a GitHub Actions workflow that runs the saved playtest regressions on every push and pull request; the same as **CI workflow…** in the findings panel (see [Review](Review.md)). |
| Live game | `game_tree`, `game_get` (read), `game_set`, `game_call`, `game_wait`, `game_input` | With the game running (launched by `run_scene`, or a manual run with «Use the playtest autoload also when running the game manually»): the live node tree, read and change properties, call methods, wait until an expression is true or a signal is emitted, and send keys, actions, clicks and joypad input, by time or by physics frame (the same sequence plays the same at any framerate). Changes are live only; the scene files stay as they were. Game errors raised meanwhile come back with the result. |
| | `game_find`, `game_ui` (read), `game_ui_act` | Find nodes by class, group or name. See the game's texts and controls with their ids, and use them with a real click: something on top of a control blocks it and comes back as an error. |
| | `game_pause`, `game_step` | Pause the game and advance it exact physics frames with input: play turn by turn, even a fast game. |
| | `game_script` | A short GDScript that runs inside the game: many reads and inputs in one call, reacting in the same frame. It stops at its timeout, lets go of the keys and can't use files or start processes. |
| | `game_watch`, `game_frames` (read) | What changed in some nodes during a time window, with times, and the frames of the last seconds (with `film_fps` on `run_scene`). |
| | `game_monitors` (read) | Godot's performance monitors, sampled every frame for a few `seconds` (optionally while playing `steps`): frame time (average, p95 and max), the engine's slowest process and physics frame of each second, draw calls, objects and primitives drawn, awake physics bodies and collision pairs, and nodes, orphan nodes, objects, resources and static and video memory at the start and end of the window (a count that keeps growing is a leak). It also lists the orphan nodes, grouped by name, class and script: nodes created and never added to the tree, or removed without `free()`. `profile_run` only measures GDScript; this shows a game that is slow because of rendering or physics, or that leaks nodes. |
| GDExtension | `build_extension`, `test_extension`, `install_extension`, `restart_editor` | For projects with a native extension (godot-cpp with SCons or CMake, or gdext with Cargo). `build_extension` builds it and returns the compiler errors by file and line; it never loads the build into the open editor. `test_extension` tests it in a separate headless Godot, so a crash kills only that process, and returns the failed checks and, after a crash, the backtrace. `install_extension` brings the tested extension from its test project into the game as an addon, only if the tests pass. Nothing changes in the open editor: the files wait until the next restart. `restart_editor` saves the scenes and restarts the editor so it loads the new build, under the crash supervisor by default; the agent's session resumes afterwards. Tested on Linux; Windows and macOS are not verified yet. |
| Sessions | `sessions`, `session_send` (read) | With several agent sessions open in the editor: list the others (name, mode, state, what each is working on, the files it's editing in its current turn, which one has the game running), and send one a short message (up to 4,000 characters). The message reaches that agent as a prompt when its current turn ends, marked as coming from the sender. |

## Details

- **Undo**: each scene edit is one step of the editor's undo. The tool card in the chat has **↶ undo** while nobody has touched the scene afterwards.
- **Open scenes**: the agent is told to edit open scenes through these tools, never on disk.
- **Playtests**: `run_scene` adds a temporary autoload that captures errors, frames and simulated input, and removes it as soon as the game starts. If the editor dies mid-playtest, the next start cleans it up. The export never includes it.
- **GDExtension**: a build that crashes the editor would take your work with it, so new builds are tested outside the editor and only loaded on a restart. Under the **crash supervisor** (a headless Godot that opens the editor and watches it), a build that crashes the editor while starting is replaced by the last one that started fine and the editor reopens; the agent's session continues with a message that says what happened. If the editor is closed while an install from `install_extension` is waiting, the dock says so the next time it starts, with **Restart** to load it and **Discard** to drop it.
- **Long calls**: a call that takes longer than 2 seconds (a long `run_scene` or `profile_run`, `build_extension`, `test_extension`, a C# `validate_scripts`, an Asset Store download, or any call waiting on its permission card) answers as an event stream with a progress notification every 10 seconds, when the client asks for progress (Claude Code and Google Antigravity do); for other clients it stays a plain answer. Without it, Claude Code stops waiting for an HTTP tool after 60 seconds with no response. Progress resets Claude Code's 5-minute idle limit, but not a total limit you set with `MCP_TOOL_TIMEOUT` or a server `timeout`: keep that above 120 seconds, the longest `run_scene`. The stdio bridge passes each event on as it arrives.
- **Tool hints**: each tool tells the client whether it only reads (`readOnlyHint`), can overwrite or delete (`destructiveHint`), is safe to repeat (`idempotentHint`) or reaches the internet (`openWorldHint`), from its permission group. Claude Code runs read-only calls in parallel. The harness still asks permission by group, whatever the client does with the hints.
- **Project map**: `project_map` follows the links Godot uses, which grep doesn't see: scripts attached in scenes, instanced scenes, resources in `.tscn` and `.tres` files, saved signal connections, `preload`/`load` paths, `class_name` and autoload names in code, `extends` and groups. It ranks the files by how close they are to the focus, so a script that half the project uses (the player, a global state) doesn't crowd out the focus's own neighbours. The first call indexes the project in the background (about 3.5 seconds for 750 scripts, 300 scenes and 350 resources); later calls reuse what didn't change and take about half a second. Its text comes in an untrusted envelope, because it includes names and signatures written in the project.
- **Untrusted text**: what the game prints, its errors, what the game tools read from the running game, the texts of scenes and resources (`scene_tree`, `get_node`, `get_resource`, `animation_get`) and what comes from the Asset Store arrive inside `<untrusted nonce="…">…</untrusted nonce="…">`, with a new random nonce in each call. The agent is told to read that text as data and never follow it, so a game or an asset that writes "ignore your rules and…" can't give it orders. The text can't close the envelope early: it doesn't know the nonce, and any `<untrusted` tag it brings is escaped. The same goes for the `@output` mention and the **Fix with the agent** prompt after a manual run. This lowers the risk of prompt injection, mainly in Auto mode; it doesn't remove it.
- **Limits**: **Settings → MCP server** sets the characters per result and the maximum image side, plus extra folders outside the project that the agent may read and write.
- **Security**: the server only listens on `127.0.0.1`, requires a token that changes on every start (**Regenerate token** in Settings), and the token is masked wherever it could show: the log, the chat, the cards, the saved history.
